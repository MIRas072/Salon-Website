# Как подключить кабинет администратора

Сайт салона умеет принимать заявки в облачную базу Firebase (сервис Google) и показывать их в кабинете `admin.html`.
Это бесплатно: для небольшого салона хватает бесплатного тарифа Spark.

Пока вы не выполнили шаги ниже, всё работает по-старому: запись на сайте уходит в WhatsApp, а кабинет показывает подсказку.

Время: около 15 минут. Аккаунт Google нужен ваш личный, создавайте всё сами.

---

## Шаг 1. Создайте проект Firebase

1. Откройте https://console.firebase.google.com и войдите в аккаунт Google.
2. Нажмите **Create a project** (Создать проект).
3. Название: например `salon-11`. Нажмите Continue.
4. Google Analytics можно **выключить**. Нажмите Create project и дождитесь готовности.

## Шаг 2. Добавьте веб-приложение и скопируйте настройки

1. На главной странице проекта нажмите значок **`</>`** (Web).
2. Название приложения: `salon-site`. Галочку «Firebase Hosting» **не ставьте**. Нажмите Register app.
3. Появится блок кода с `firebaseConfig`. Нам нужны 4 значения: `apiKey`, `authDomain`, `projectId`, `appId`.
4. Откройте файл `firebase-config.js` в папке `salon` и вставьте эти значения между кавычками:

```js
window.SALON_FIREBASE = {
  apiKey: "AIza...",
  authDomain: "salon-11.firebaseapp.com",
  projectId: "salon-11",
  appId: "1:123456789:web:abcdef"
};
```

Эти значения не секретные, их можно хранить на сайте. Защита данных настраивается правилами (шаг 5).

## Шаг 3. Включите вход по почте и создайте аккаунт администратора

1. В меню слева: **Build → Authentication → Get started**.
2. Вкладка **Sign-in method** → выберите **Email/Password** → включите первый переключатель → Save.
3. Вкладка **Users** → **Add user**. Введите вашу почту и **надёжный пароль** (не такой же, как в других местах). Это ваш вход в кабинет.
4. Запомните почту: она понадобится на шаге 5.

## Шаг 4. Создайте базу данных

1. В меню слева: **Build → Firestore Database → Create database**.
2. Расположение: выберите ближайшее к вам в Европе (например `eur3` или `europe-west3`).
3. Режим: **Start in production mode** (рабочий режим). Нажмите Create.

## Шаг 5. Вставьте правила безопасности

Правила решают, кто что может делать с данными: любой посетитель может **только отправить** заявку, а читать и менять заявки может **только вы**.

1. В Firestore откройте вкладку **Rules**.
2. Удалите всё, что там есть, и вставьте содержимое файла `firestore.rules` из папки `salon`.
3. Проверьте почту в функции `isAdmin()`: сейчас указана `jokkerazirali@gmail.com`. Она должна совпадать с аккаунтом из шага 3. Для другого администратора замените почту, сохраняя кавычки.
4. Нажмите **Publish**.

## Шаг 6. Опубликуйте сайт заново

1. В Netlify откройте ваш сайт салона → **Deploys** → перетащите папку `salon` целиком.
   (Если сайт салона ещё не публиковали: **Add new project → Deploy manually** и перетащите папку `salon`.)
2. Кабинет будет по адресу: `https://ваш-сайт.netlify.app/admin.html`
3. Добавьте этот адрес в закладки на телефоне. Ссылки на кабинет на самом сайте нет, это нормально.

## Шаг 7. Проверьте

1. Откройте сайт, заполните форму записи и отправьте.
2. Откройте `admin.html`, войдите. Заявка должна появиться вверху в разделе «Новые».
3. Нажмите «Подтвердить», затем «WhatsApp»: откроется чат с клиентом и готовым текстом подтверждения.

---

## Что умеет кабинет

- Заявки с сайта появляются сами, без обновления страницы.
- Фильтры: **Новые**, **Сегодня**, **Предстоящие**, **Все**. Поиск по имени и телефону.
- Статусы: Новая → Подтверждена → Выполнена, либо Отменена. Можно вернуть обратно.
- Кнопки **Позвонить** и **WhatsApp** (с готовым сообщением клиенту).
- Кнопка **+ Новая запись**: добавить клиента вручную (например, пришёл по звонку).
- **Изменить**: перенести время, поправить услугу или телефон.
- Выбор мастера и расписание на день с занятыми и свободными окнами.
- Проверка конфликтов отдельно для каждого мастера; разные мастера могут принимать клиентов одновременно.

## Мастера и свободные окна

Мастера настроены в `schedule.js`:

- **Назигуль** (`master-1`) — все услуги.
- **Арай** (`master-2`) — все услуги, кроме свадебного образа.
- **Жазира** (`master-3`) — только мужской зал.

После выбора услуги клиент видит только подходящих мастеров. Выбор мастера и даты загружает актуальное расписание. Занятые окна показываются с отметкой **«Занято»** и недоступны для выбора. Имена и телефоны других клиентов не отображаются. Если выбранное окно занял другой клиент, выбор сбрасывается.

График сейчас общий: **ежедневно 10:00–20:00**, последнее начало — **19:30**. Каждая запись занимает **одно окно 30 минут**, независимо от услуги. Это текущая модель: длительность окрашивания, свадебного образа и других долгих услуг пока отдельно не учитывается. Даты и прошедшее время проверяются по времени Астаны (UTC+5), независимо от часового пояса устройства.

Новая заявка сразу занимает окно, ещё до подтверждения администратора. Для резервирования используется отдельная коллекция `availability`, где находятся только ID мастера, дата, время и технический ID записи. Персональные данные остаются в закрытой коллекции `bookings`.

Запись и резервирование сохраняются одним атомарным пакетом. Правила запрещают перезаписывать занятое окно. При переносе, смене мастера, отмене, завершении или удалении кабинет меняет запись и резервирование одной транзакцией. Восстановление отменённой записи возможно только если окно свободно.

### Как включить обновлённую систему

1. Заполните `firebase-config.js` и настройте Firebase по шагам выше.
2. Опубликуйте обновлённые `firestore.rules`, проверив почту администратора в функции `isAdmin()`. Старые правила не разрешают поле `masterId` и не защищают резервирование окон.
3. При наличии старых активных записей назначьте каждой мастера через **«Изменить» → «Сохранить»**. Это создаст резервирование. До переноса старых записей в новый формат они не блокируют время на сайте; кабинет показывает предупреждение о записях без мастера. Проверьте их перед открытием записи клиентам.
4. Опубликуйте файлы сайта, обязательно включая новый `schedule.js`: `index.html`, `style.css`, `booking.js`, `admin.html`, `admin.css`, `admin.js`, `firebase-config.js`, `schedule.js`. Файлы тестов и инструменты разработки для публикации сайта не нужны.
5. Отправьте тестовую заявку на свободное время. Откройте сайт во втором браузере — время должно стать занятым. Отмените запись в кабинете — окно должно освободиться. Проверьте перенос и возможность записи к другому мастеру в то же время.

Имена можно менять в `schedule.js`, сохраняя постоянные ID мастеров. При изменении списка услуг, ID мастеров или рабочих часов синхронно обновляйте ограничения в `firestore.rules`. Не удаляйте документы `availability` вручную: освобождайте окна через действия с записью в кабинете.

Пока Firebase не подключён, форма передаёт выбранного мастера и желаемое время в WhatsApp. В этом режиме сайт явно сообщает, что занятость неизвестна: окно в базе не резервируется.

Локальные проверки описаны в [tests/README.md](tests/README.md).

## Безопасность и данные клиентов

- Пароль никому не передавайте. Если перестали доверять устройству, смените пароль в Firebase (Authentication → Users).
- Дополнительно можно запретить регистрацию новых пользователей: Authentication → Settings → User actions → снимите «Enable create (sign-up)».
- Сайт хранит имя и телефон клиента только для записи. На странице формы есть пояснение об этом. Если нужен полноценный документ о политике обработки данных (по законодательству Казахстана о персональных данных), составьте его отдельно.
- Бесплатный тариф Spark ограничен по числу запросов в сутки, но для салона этого с большим запасом.

## Если что-то не работает

- **В кабинете надпись «Кабинет пока не подключён»**: значения в `firebase-config.js` пустые или файл не загрузился на сайт. Проверьте шаг 2 и опубликуйте сайт заново.
- **«Неверная почта или пароль»**: проверьте шаг 3 (пользователь создан именно в Authentication → Users).
- **«У этого аккаунта нет доступа к записям»**: в правилах (шаг 5) почта не совпадает с вашей. Исправьте и нажмите Publish.
- **Форма пишет «Не удалось отправить заявку»**: проверьте правила (шаг 5) и что база создана (шаг 4).
